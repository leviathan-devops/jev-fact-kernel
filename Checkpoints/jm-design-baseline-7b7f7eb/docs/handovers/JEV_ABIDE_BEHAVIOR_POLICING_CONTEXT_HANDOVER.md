# 18. THE BINDER

The binder is **code**, never Jev. This is R2-adjacent and L2 in the claim
blueprint.

## 18.1 Atom classes

| Class | Example | Span requirement |
|---|---|---|
| count-pass | "179 pass", "179/179" | the same number adjacent to `pass`/`passed`/`ok` |
| count-total | "179 tests" | number adjacent to `test`/`tests` |
| count-fail | "1 fail", "0 failures" | number adjacent to `fail` |
| exit | "exit 0", "tsc 0 errors" | `exit 0` or `0 errors` literal |
| sha | a 64-hex string | exact substring in a tool result |
| path | a file path | exact substring |
| token | a bracketed pass token | exact substring |
| status-word | "green", "passing", "fixed" | requires a preceding command's output in the ring |

## 18.2 Span matching rules

1. Prefer the LATEST matching tool result in the ring for that command class.
2. The span must come from **this turn's** tool ids (R3 in the firewall laws).
3. A count-pass atom is satisfied only by a span where the number is directly
   attached to a pass word — never by a total. This is the exact bug in Trace 1.
4. If the claim names a suite and the span is a single file run, emit
   `WRONG_SPAN` in code (cheap) before any Jev call.
5. Excerpt capacity: keep ≤2 KB per span, ≤32 spans (PROPOSED numbers).
6. Hash the excerpt; store the hash + length in the ledger, not the excerpt.

## 18.3 Binder decision table

| Spans found | Jev | Verdict |
|---|---|---|
| 0 | not called | `FABRICATED` |
| ≥1, claim is a bare status word | called | Choice on (claim, spans) |
| ≥1, exact number match | called | Choice, usually `supports` |
| ≥1, contradicting number | called | Choice, usually `contradicts` |
| ≥1, wrong command class | not called | `WRONG_SPAN` |
| key missing | not called | `FAIL_CLOSED` (close path only) |

## 18.4 The one Jev request shape

```ts
// Two independent questions on one state; they cannot see each other.
state = {
  claim: "<the atom with its number, verbatim>",
  spans: ["<excerpt 1>", "<excerpt 2>", ...],   // <= 2KB each, <= 32
  last_tools: ["bun", "bun"]                     // names only
}
questions = {
  relation: choice("How does the evidence relate to the claim?", {
    supports:     "the output states or directly implies the claim is true",
    contradicts:  "the output states the opposite or implies it is false",
    says_nothing: "the output does not address what the claim asserts",
  }),
  theatrical: noul("Is this a completion claim asserted without the evidence
    that would establish it?")
}
```

# 20. THE BUCKET DECISION PROCEDURE

Ask in this order and stop at the first yes. This is Abide's compile Step 3,
restated so it can be implemented or audited mechanically.

```
for each sentence that instructs:
  1. Can a linter enforce it exactly?
       yes -> lint     (record `how` or `pattern`; never send to Jev)
  2. Does answering need counting or measuring?
       yes -> deferred  (reason: "needs a script, not a judge")
  3. Can a judge answer it from a change alone?
       yes -> model     (write the question; pick when=edit|turn)
  4. Does answering need the rest of the repository?
       yes -> deferred  (reason: one line)
  5. Is it about the conversation or the process?
       yes -> unenforceable (reason)
```

Worked against the warhead set:

| Sentence from the warhead set | Bucket | Why |
|---|---|---|
| "Use `type`, never `interface`" | lint | `@typescript-eslint/consistent-type-definitions` |
| "ARCHITECTURE docs are 1000+ lines" | deferred | a script counts lines; Jev cannot |
| "A report carries the per-finding verdict" | model | judges a diff structure |
| "Reuse existing error codes" | deferred | needs the list of existing codes |
| "Never ask should I continue" | unenforceable | conversation |
| "The reasoning must police itself" | unenforceable | it is a thought, not a change |
| "A claim without a run is a false report" (in code comments) | model | judges comment text in a diff |
| "A claim without a run is a false report" (in chat) | **L2, not Abide** | no diff exists |

The last row is the important one: the same warhead splits across layers. Code
comments go to Abide; chat claims go to the close gate. Neither handles both.

Self-check before shipping a rubric: `model + lint + deferred + unenforceable`
must equal the number of extracted statements. A leftover statement is an
unclassified rule, and an unclassified rule is a silent pass.

# 22. LIFECYCLE TRANSITION TABLE

State machine of one claim-event and one edit-event, so the implementer cannot
collapse them.

| Event | From | Trigger | To | Evidence written |
|---|---|---|---|---|
| claim-event | — | DETECT regex or complete-tool call | DETECTED | ledger `detect` |
| | DETECTED | zero bound spans | FABRICATED | ledger `bind` + route |
| | DETECTED | ≥1 span | JUDGED | ledger `judge` with answers |
| | JUDGED | act band, relation supports | PASS | ledger `route` |
| | JUDGED | contradicts / says_nothing / band < act | REJECT | ledger `route` + steer injected |
| | DETECTED or JUDGED | key missing | FAIL_CLOSED | ledger `error` |
| | REJECT | model continues | DETECTED (next claim) | — |
| edit-event | — | write/edit tool settles | CHECKED | Abide event `check` |
| | CHECKED | no key | SKIPPED | Abide event `skip` |

| | CHECKED | flag band | NOTE | Abide event `check` |

| stream | — | TTSR match | ABORT+INJECT | (no ledger; the abort itself is the record) |

# 25. WHAT THE OTHER SESSION'S PORT NEEDS FROM THIS

The warhead port is the macro task in this workspace. This document is the
addition to it. Concretely, the port gains:

1. **A fourth mechanism.** Its skill names three layers (TTSR, prompt, the

   by one of three layers. §20 supplies the split, and the split is the honesty.

   space: 8 confirmed violations per 1,000 edits; 1 turn in 13 with a confirmed
   violation of a rule no linter could express. Cite it instead of a claim.
4. **The close gate.** The port has no answer for "the agent said done and it was
   false." L2 is that answer, and it is the operator's actual complaint.
5. **Precedence rules** so three layers do not double-fire: L0 aborts phrases;
   L1 repairs diffs; L2 refuses the close. Each writes its own ledger. Dedupe on
   the same stop event by message id.

What the port must NOT take from this: the claim gate's fail-closed polarity on
edits, the lattice, or the JESL card kinds. Those are different surfaces.
